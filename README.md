# H2O: ครู AI ในเกม Roblox
โปรเจกต์นี้ทำขึ้นมาเพื่อศึกษาเกี่ยวกับโค้ดภาษา Luau ในรูปแบบเกมโดยการที่หัวข้อจะเกี่ยวกับการสร้าง NPC 

NPC ในเกมส่วนใหญ่จะใช้ บทพูดที่ตายตัวหรือ การสนทนาแบบต้นไม้หรือคำสำคัญ ปัญหาที่เกิดขึ้นคือ การที่ผู้เล่นถามนอกเหนือกับคำตอบที่ตั้งไว้ จะทำให้NPCไม่สามารถตอบคำถามนอกเหนือจากที่ตั้งไว้ได้ โดยในปัจจุบันAIได้พัฒนามามากพอที่จะตอบคำถามต่างๆได้เป็นธรรมชาติ ผมเลยทำการใช้ API ของ AI จาก OpenRouter มาใช้โดยกำหนดบทบาทให้แก่ AI เป็น คุณครูวิชาการ ที่ตอบคำถามเกี่ยวกับการเรียนและความรู้ทั่วไป

## ทำอะไรได้บ้าง
-  ถามคำถามทั่วไปเกี่ยวกับการเรียนและความรู้ทั่วไป
-  สามารถควบคุมอยู่ในบทบาทของคุณครูได้
-  สามารถจำคำถามก่อนหน้าได้ ใน 6 ข้อความก่อนหน้านี้และจำแยกตามผู้เล่นแต่ละคน
- มีcooldownเพื่อกันการกดหลายครั้งจำกัดไว้เพื่อไม่ให้โควตาการใช้งาน model free หมด
-  มีระบบการกรองคำพูด ตามกฎของ Roblox
-  มีระบบmodel AI 3 ตัวและมีข้อความสำรอง โดยที่จะมีคำว่า "ครูขอคิดก่อนนะคะ","ครูกำลังยุ่งมากๆอยู่ค่ะ","ครูกำลังยุ่งอยู่ค่ะ" เป็นคำสำรอง

## ระบบทำงานยังไง
1. ผู้เล่นพิมพ์คำถามใน TextBox แล้วกดปุ่ม LocalScript จะส่งข้อความไปให้ server ผ่าน RemoteEvent `AskH2O`
2. Server รับข้อความด้วย `OnServerEvent` และรู้ด้วยว่าผู้เล่นคนไหนเป็นคนส่งมา
3. Server เช็กก่อนว่าข้อความที่ว่างไหม และพ้น cooldown 5 วินาทีหรือยัง ถ้าผ่านก็จดข้อความนั้นไว้ลงสมุดความจำ
4. ฟังก์ชัน `askAI` ส่งบทครู (system prompt) และคำถามในสมุดไปที่OpenRouter โดยใช้ API key ที่เก็บไว้ในSecrets ของ Roblox	
5. ฟังก์ชัน `filterText` กรองคำตอบด้วยระบบของ Roblox แล้วแสดงบนข้อความเหนือหัวครู H2O

## ความปลอดภัย
- API key เก็บไว้ในSecrets ของ Roblox ซึ่งในโค้ดมีแค่ชื่อ ไม่มีตัว key จริงจะใช้ชื่อAPI Key ว่าPROJECT
- เพื่อทำให้ผู้เล่นไม่เห็นPrompt และกันการขโมย key apiและเรียก AI จากฝั่ง server เพราะ GetSecret กับ HttpService ใช้ได้เฉพาะฝั่ง server

## ข้อจำกัดและสิ่งที่จะพัฒนาต่อ
- ยังไม่ได้จำคำตอบของครู
- โมเดลฟรีช้าหรือคิวเต็ม
- ป้ายใช้ร่วมกันทุกคน

## สิ่งที่ได้เรียนรู้
- ตอนที่ pcall ได้ true แต่ API ตอบ 429 ต้องเช็กทั้ง success และ StatusCode == 200 ถึงจะแน่ใจว่าได้คำตอบจริง 
- AIได้เฉลย 12 x 15 เพราะมองว่าคำตอบนั้นง่ายเกินไป จึงกำหนดให้ชัดเจน
- ถ้าไม่มี choices ป้ายจะค้างที่ "อืม...." เพราะอยู่นอก pcall จึงแก้โดยเช็กทั้งสองตัว ได้แก่ choices และ choices[1] เพื่อกันให้สามารถรันบรรทัดต่อไปได้โดยไม่มีปัญหา ถ้าไม่ผ่าน จะใช้คำสำรองที่พูดว่า "ครูไม่ได้เข้าใจคุณ ลองพิมพ์ใหม่ดูนะคะ" แทน
- ถ้า server ตอบกลับมาไม่ใช่ JSON อาจจะเกิด error ขึ้นได้ แต่มีโอกาสน้อยมากๆ ที่ OpenRouter จะส่งกลับมานอกเหนือ JSON ผลที่เกิดจะทำให้ป้ายของH2O ค้างที่คำว่า "อืม...." เพราะว่า error ในส่วนของการแปลงคำตอบ


## วิธีลองรัน
1. ต้องมี OpenRouter API key ของตัวเอง
2. ตั้ง Local Secret ชื่อ PROJECT (domain openrouter.ai)
3. เปิด Allow HTTP Requests
4. วาง Script ไว้ใน ServerScriptService / วาง LocalScript ไว้ใน ScreenGui / มี RemoteEvent ชื่อAskH2O ไว้ใน ReplicatedStorage
5. ⚠️ ห้ามใส่ API key ไว้ในโค้ดเด็ดขาด
